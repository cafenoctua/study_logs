# レビュー方針(Claude と人間の役割分担)

## Claude が見る(この順)
1. intent / plan との一致
2. 正しさ(SQL): 結合キー、粒度の変化、NULL、incremental 条件
3. 正しさ(Rust): 本番経路の `unwrap()` / `expect()`、エラーの握りつぶし、SQL への未エスケープの埋め込み
4. テスト: 必須テストの有無、テストの改変(`crates/*/tests/` と schema.yml)
5. 下流と MetricFlow への影響(`forge ls --select <model>+`)
6. コスト(全件スキャン、不要な table 化)
7. セキュリティ(秘密情報、権限)

## 深刻度と件数上限
| 深刻度 | 意味 | 上限 |
|---|---|---|
| blocker | マージ不可 | 全件 |
| major | 直すべき | 全件 |
| minor | 直すと良い | 5件 |
| nit | 好み(`cargo fmt` / `clippy` で直るものは指摘しない) | 3件 |

## 要人間確認
仕様の妥当性・業務上の意味は判定せず、末尾に「要人間確認」として列挙する。

## 人間が見る
意図とリスク。最終承認は人間のみ(Claude のレビューだけではマージしない)。
